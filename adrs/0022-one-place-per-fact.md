# HW-0022: One place per fact, and a command instead of an answer

**Status:** Accepted

**Date:** 2026-09-22

## Context

Facts copied between documents drift, and this repository has the receipts.

`operations.md` §6 said for four releases that this site lacked
`configure-host.py`, which podpack had shipped since 0.7.1, "because nothing
made the two agree". Worse, §6 had never mentioned `scripts/restore.sh` at all —
it documented `dropdb`, `createdb` and `pg_restore` by hand instead, and
`ops/rebuild.md` inherited that hand-rolled sequence from it. **Both of the
first rehearsal's expensive defects follow directly from that.**

Version snapshots were overtaken three times on one page — "Current as of
2026-08-23" recording substrate 0.9.0b2 against a real 0.9.1 — and a claim of
fifteen integration tests was made against a suite of twenty-six.

`PROJECT-BRIEF.md`'s predecessor failed differently but as thoroughly: the
system moved under it wholesale, so it was replaced rather than amended.

## Decision

Each fact has one owning document; the others link to it.

**A reference records a number only when the running system cannot be asked.**
Where it can, the document gives the command instead of the answer. Any snapshot
that is kept carries its date.

**A browser copy of a procedure is generated from the markdown, never
maintained beside it.**

## Consequences

**`PROJECT-BRIEF.md` is deliberately thin on specifics** and reads as a set of
pointers — less use to somebody without the system in front of them, which is
the price of it not being able to lie.

**Cross-references have to be repointed whenever a file moves**, and the rule
reduces drift without stopping it: the 2026-09-21 reconciliation still found
twelve claims the tree had outgrown.

**Only two of the six browser copies are actually generated by anything this
repository owns.** `rebuild.html` comes from `ops/render-rebuild.py` — which
renders rather than duplicates, so it cannot diverge, and which also buys a copy
button on every command block and linked export forms the markdown cannot have —
and `ops/messages.html` from `ops/build-messages.py` (HW-0026). The other four
are mdpdf output, untracked, produced by a command that appears nowhere in the
tree. The rule is tooled where it was instrumented and is a habit everywhere
else.

## Alternatives considered

**Keep the facts in each document and re-audit periodically.** That was the
position, and it failed three times on one page before it was abandoned.

**Maintain the browser copy by hand.** Rejected: "two hand-maintained copies of
one procedure is precisely the arrangement that let `operations.md` claim for
four releases that this site lacked a script it already had."

**Generate the reference documents too**, from the system itself. Not attempted;
the command-instead-of-an-answer rule is the cheap approximation of it.
