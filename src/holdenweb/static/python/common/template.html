Headings and prose

Body text sits in a single comfortable reading column. Links look like this, and inline code such as len(seq) is set in a monospace face with a soft tint.

A subheading

Subheadings introduce a finer level of structure within a section.

  • Lists keep their bullets and comfortable spacing.
  • Nesting and ordering both behave as you would expect.
Code

The white box holds a block of code. The inserted parts show new code to add; the struck-through parts show code to remove.

Code
def greet(name):
    """Return a friendly greeting."""
    print("Hello, " + name)
    return f"Hello, {name}!"

print(greet("Guido"))
Code and output

The dark box shows code together with the result it produces. On a notebook platform this is simply a code cell and its output.

Code and output
>>> invites = ["Steve", "Danny", "Larry", "Guido"]
>>> attendees = [3, 2, 0, 5]
>>> sum(attendees)
10
>>> party = list(zip(attendees, invites))
>>> party
[(3, 'Steve'), (2, 'Danny'), (0, 'Larry'), (5, 'Guido')]
Observe

The grey box is for reading and absorbing — often colour-annotated code that the following prose explains.

Observe
for i, name in enumerate(invites):
    print(f"{i}: {name}")

Modernization note (new)

Where the original code predates current idiom, I will flag it inline in a callout like this one, so it is visibly distinct from your lesson text and easy to accept or reject:

Modern Python The original concatenates with "Hello, " + name. Today an f-string — f"Hello, {name}!" — reads better and handles non-string values. (Python 3.6+.)
